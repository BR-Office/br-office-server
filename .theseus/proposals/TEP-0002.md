## Problem
All 7 first-review approvals in AUD-1 were repository-only packets: PKT-0001, 0003, 0004, 0005, 0007, 0013 and 0014. Every first-review failure and every costed block needed something outside the repository:
- a Document Server stack: PKT-0015, PKT-0016
- the GitHub API: PKT-0015, PKT-0017
- a file outside the target: PKT-0002

The same pattern shows in the friction lines. PKT-0016 says environment.md lacked the DB password and did not say that systemctl is missing. PKT-0017 says environment.md wrongly said the GitHub API was unavailable. `permission_denials` is non-empty in 14/14 records, including plain `cat`, `ls` and `grep` reads.

## Proposed change
1. A packet gets a new field, `requires: [<resource>]`, for example `docserver`, `gh-api` or `network`.
2. Each resource has a check command in `adapter/environment.md`.
3. Before it claims such a packet, the factory runs the check commands. If a check fails, the packet stays in `pending` with a recorded reason and costs no agent time.
4. In the adapter, read-only shell commands (`cat`, `ls`, `grep`, `head`, `sed -n`, `wc`) are on the allowlist by default.

## Hypothesis
"With the preflight, the first-review approval rate of packets that declare `requires` rises from 0/3 (AUD-1) to at least 50%. The cost per done packet that needs the environment falls by 30%, and the approval rate of repository-only packets stays the same."

## How to verify
Compare first-review approval and cost per done packet, split by whether `requires` is empty, and count the permission denials per record. Minimum sample: 5 packets that declare `requires`.

## Risks
Check commands go stale and report false passes. This shows up as rejections that cite the environment even though the preflight passed.
