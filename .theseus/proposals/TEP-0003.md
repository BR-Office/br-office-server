## Problem
In PKT-0016, a reviewer wrote that "the acceptance check passes trivially": the deliverable file existed but contained no measurements. Acceptance on `investigate` packets is usually `test -s <file>`, and so is AUD-1's (PKT-0020). This leaves the reviewer as the only oracle. It cost review rounds in PKT-0015, PKT-0016 and PKT-0017 (AUD-1 O3).

## Proposed change
Add to the work packet spec: "At least one acceptance command must fail unless the Goal's main result is present. Examples: `grep` for the required table, section or number pattern, or a script that checks for the measured values. A bare `test -s` or `test -f` is not enough." Make `theseus validate` warn when every acceptance command is an existence test.

## Hypothesis
"Requiring content checks in acceptance cuts the number of review rejections that cite an unmet Goal clause by at least 40%, while the time to write a packet and the false-fail rate of acceptance commands do not grow by more than 10%."

## How to verify
Count rejections per done packet that cite the Goal (AUD-1: 14 over 10 done packets) and acceptance failures later judged wrong by the reviewer. Minimum sample: 15 `investigate` packets.

## Risks
Brittle `grep` checks fail good work, or agents game the checks with placeholder text. Both show up in the review: wrong acceptance failures in the first case, placeholder rejections in the second.
